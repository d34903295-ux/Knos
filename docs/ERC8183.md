# Knos and ERC-8183 (Agentic Commerce)

`contracts/KnosEscrow.sol` (0.3.6) implements the ERC-8183 job interface beside the Knos jobs it already had.
Same token, same fee, same guard rails (pause stops new funding, minimum job, per-job cap); the two job books are separate
(Knos jobs are keyed by `bytes32`, ERC-8183 jobs by a `uint256` counter). Source: https://eips.ethereum.org/EIPS/eip-8183 (Draft).

## Roles

| Knos | ERC-8183 |
|---|---|
| buyer | client |
| worker | provider |
| verifier | evaluator |
| guardian | (none: may pause new funding and lower the cap, never touches funds) |

## States

| Knos (`S`) | ERC-8183 (`JobStatus`) |
|---|---|
| (job id reserved, not funded) | Open |
| Open / Claimed | Funded |
| Delivered | Submitted |
| Released | Completed |
| Refunded (reject) | Rejected |
| Refunded (no delivery by the deadline) | Expired |

## Functions

| Knos | ERC-8183 | Who |
|---|---|---|
| `post` / `postWithVerifier` | `createJob(provider, evaluator, expiredAt, description, hook)` + `setBudget` + `fund` | client creates and funds; provider sets the budget |
| `claim` | `setProvider(jobId, provider)` | client (Knos: the first worker to claim) |
| `deliver(id, result)` | `submit(jobId, deliverable, optParams)` | provider |
| `verifyRelease(id, resultHash, proofRoot)` | `complete(jobId, reason, optParams)` | evaluator only |
| `reject(id)` (buyer) | `reject(jobId, reason, optParams)` | client while Open; evaluator once Funded/Submitted |
| `refund(id)` | `claimRefund(jobId)` | anyone, after `expiredAt`; not hookable |
| `accept(id)` / `release(id)` | (none: only the evaluator completes) | |
| `jobs(id)` | `getJob(jobId)` | view |

## Events

| Knos | ERC-8183 |
|---|---|
| `Posted` | `JobCreated`, `BudgetSet`, `JobFunded` |
| `Claimed` | `ProviderSet` |
| `Delivered` | `JobSubmitted` |
| `Proven` + `Released` | `JobCompleted` + `PaymentReleased` |
| `Refunded(bytes32)` | `JobRejected` or `JobExpired`, then `Refunded(uint256,address,uint256)` |

## The Knos verifier rule

- **The evaluator can never be the provider.** Refused in `createJob` and `setProvider`, and checked again in `complete`.
- **When an evaluator is named, only it or expiry settles the job.** Once funded, only the evaluator can `complete` or
  `reject`; the client cannot reject. After `expiredAt` anyone can `claimRefund` to the client, even while paused;
  nothing (no hook, no pause, no party) can block it.
- **Fee only on Completed**: `fee = max(feeBps of the budget, minFee)`, paid to `feeTo`. Rejected and Expired refund the full budget.
- `expiredAt` must be more than 5 minutes ahead; `evaluator` must be non-zero; no hooks are whitelisted, so `hook` must be zero.
- `optParams` are accepted and ignored. `reason` (bytes32) carries the evaluator's attestation, e.g. the proof root.
